# [sync] Settings nav peer-stale badge removed; silent observer peer alert; per-peer stale note and silence setting in the Observer screens (datawatch v9.132.0)

**Not filed yet.** This is the tracked draft. The operator opens the issue on the
datawatch-app repo when they choose to. Writing this file files nothing and changes
nothing outside this repo.

## What changed on the web app (PWA)

Four changes, all visible to the operator:

1. **The Settings nav button no longer shows a red stale-peer count badge.** The badge
   element, its 30-second poll of `GET /api/observer/peers` (which ran on every
   screen) and its tap-through to the Observer screen are gone.
2. **Each row in the Observer peer list can show an inline warning note.**
   - "Stale (age)" when the peer last pushed more than 60 seconds ago. The age is the
     relative age the row already shows.
   - "Never pushed" when the peer has never pushed.
   - The daemon's own row (`is_self`) never shows the note.
   - It reads `last_push_at` from the existing peers response. No new endpoint.
3. **A new Settings field, Observer peers section: "Silent peer alert after (minutes;
   0 = disabled)"**, with a hint, reading and writing `observer.peers.silent_alert_minutes`.
4. **Two new system alerts reach the Alerts list**, raised by the daemon (see below).
   They need no PWA code. The alerts list already renders system alerts.

## What the daemon now does

- A watcher checks every registered observer peer once a minute. The daemon's own row
  is skipped.
- A peer that has not pushed for longer than the threshold raises one warning system
  alert, "Observer peer silent: <name>", naming the peer, the silence length, the
  threshold and the last push time. A peer that never pushed is measured from its
  registration time. It raises one alert per outage, not one per check.
- When that peer pushes again, one info alert, "Observer peer recovered: <name>",
  follows. A peer deleted during an outage is dropped without an alert.
- The watcher only runs when the observer peer registry is on
  (`observer.peers.allow_register` is true). With registration off, no alert is raised.
- The alert goes through the normal alerts store, so any channel that forwards alerts
  forwards it too.

## Config surface

| Item | Value |
|------|-------|
| Key | `observer.peers.silent_alert_minutes` |
| Type | whole number of minutes, 0 or more |
| Default | 5 |
| 0 | turns the watcher off |
| Applies | live, no restart (the watcher reads the value on every check) |
| Set from | PWA Settings, `PUT /api/config`, `datawatch config set`, MCP `config_set`, chat `configure observer.peers.silent_alert_minutes=<n>` |
| Read from | `GET /api/config` (under `observer.peers`), `datawatch config get`, MCP `get_config`, chat `configure` help lists the key |

No new REST route, MCP tool, or CLI command was added. The peers response is unchanged.

## Expected behavior in the mobile apps (Android and iOS)

- Remove the Settings-entry stale-peer count badge and any separate peers poll behind
  it, if the app built it.
- Show the same inline note on each peer row in the Observer peer list: "Stale (age)"
  past 60 seconds since the last push, "Never pushed" if it has not pushed. Skip the
  daemon's own row.
- Add the "Silent peer alert after (minutes)" number field (minimum 0, 0 = disabled)
  to the Observer settings, reading and writing `observer.peers.silent_alert_minutes`,
  with the same label and hint wording in the app's locale bundles.
- Show the two alerts like any other system alert. Do not copy the watcher into the
  app: it runs only in the daemon.
- Do not add a Vault badge to the Settings entry either. The PWA has none.
