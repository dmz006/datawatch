# Automata Events sub-tab: one merged event log, moved cards, new REST read, 25 locale keys

## Body of the issue

The PWA gained an Events sub-tab on the Automata view. It shows one newest-first list of Automata events merged from the watch, lane fill decisions, infrastructure retries, checks, safe-to-delete, cleanup, repo CI watch and error sources. Several cards left the Automation tab for it. The app should add the same sub-tab, the same filters and the same paging, and drop the moved cards from its Automation screens.

### New REST read

`GET /api/autonomous/event-log` (read-only; a federated peer needs the autonomous read capability; 503 when Autonomous is disabled; 405 for any method but GET).

| Query | Meaning |
|---|---|
| `kind` | comma list of `watch`, `decision`, `retry`, `check`, `cleanup`, `alert`, `error` |
| `project` | exact project match |
| `q` | case-insensitive text over summary, detail, project, automaton and automation |
| `limit` | 1 to 200, default 50 |
| `before` | the opaque `next_cursor` of the previous page |

A bad limit, cursor or kind is a 400. Response: `{"events": [...], "next_cursor": "", "total": N}`. `next_cursor` is empty on the last page; `total` counts every event matching the filters. Each event has `id`, `time`, `kind`, `summary`, `severity` (`info`, `warn` or `error`) and, when present, `project`, `automaton`, `automation`, `detail`, `reason`, `next_action` and `quiet`.

### Other surfaces added (no app work needed, listed for completeness)

- MCP tool `autonomous_event_log` (filters `kind`, `project`, `q`, `limit`, `before`; capability `autonomous_read`).
- CLI `datawatch autonomous event-log`.
- Comm channel `autonomous event-log [kind=K] [project=P] [q=TEXT] [limit=1..10] [before=CURSOR]`.

### PWA behaviour to match

- Events sub-tab on Automata: kind chips send `kind=`, a project dropdown sends `project=`, a debounced search box sends `q=`, and Load more follows `next_cursor` with `before=`.
- Moved into Events: Supervisor watch, infrastructure retries, Automata checks, safe to delete and cleanup status (each keeps a help line). The Inbox no longer has the supervisor watch card; Resources no longer has the infrastructure retries and checks cards; Housekeeping keeps only uncommitted work and protected paths.
- The repo CI watch no longer has a permanent line in the sub-tab bar; its failing, pending and never-polled states arrive as Events entries and alerts. Off statuses never appear as a permanent strip.
- Rows with an error show What happened, Reason and Next action, with an Open and fix link.
