Parent release: datawatch v9.99.0 (automation requirements report and model pull consent).

**Screens.** (1) Setup: a "Requirements report" card (capabilities with their minimum Ollama version and whether each node meets it, the backends configured per workload, and what is missing) and a "Model pull consent" card (pull-allowed models with notes, the publisher allow-list, add, remove and save). (2) Settings: a "Minimum Ollama overrides" section, one version field per capability, empty meaning the built-in floor. (3) The compute node detail: a "Backend versions" row with below-minimum and not-installed flags, loaded when the node is expanded.

**API contract.**
- `GET /api/automation/requirements-report` (`?format=json` or `text`): capabilities, nodes (`meets`, `fails` or `unknown` for each), backends and missing items.
- `GET` and `PUT /api/automation/model-consent`: `models[]` (`name`, `allowed`, `note`) and `publishers[]`. A `PUT` replaces the whole policy; an empty model name, a duplicate model or an empty publisher is a 400. Default-deny: a model may be pulled when it is listed as allowed or its publisher is on the list.
- `GET /api/compute/nodes/{name}/versions`: `name`, `kind`, `backend`, `backend_version`, `version_probed_at`.
- New config keys: `autonomous.requirements.min_ollama.<capability>` (a version string, empty clears the override) and `autonomous.model_pull_consent` (the whole block). Both appear in `GET /api/config`.
- Pulling a model (compute node pull, marketplace task pull) is refused with the reason when the consent policy does not allow it.
- MCP, CLI and the chat channel carry the same. OpenAPI is updated. A draft handoff is in `docs/plans/parity-issues/c1410001.md`.
