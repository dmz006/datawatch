# feat(i18n): add auto tag, stage and system tag keys for the Automation and Settings parity (datawatch v9.98.0)

**Filed:** datawatch-app issue 376.

Parent release: datawatch v9.98.0 (automatic grouping tags and Automation stages).

**Screens.** (1) Settings: an "Automatic tags" group for the `autonomous.auto_tags` block. (2) The Automation form: an optional Stage field on a member, a Rename stage action, and an "Automatic tags" section that overrides the daemon's block for one Automation. (3) The tag browser and tag filter: tags grouped under Automation, Stage, Kind and Other tags, and a "system" badge on the tags the daemon keeps (they cannot be renamed, moved or deleted; recoloring still works). (4) The progress card and the session list accept several tags with a match rule (any or all).

**API contract.**
- New config block `autonomous.auto_tags` on `GET` and `PUT /api/config`: `enabled` (default true), `automation_template`, `stage_template`, `kind_template` (placeholders `{automation}`, `{stage}`, `{kind}` only; anything else is a 400 that names the key) and `kind_labels` (feature, bug, other mapped to label strings). Config keys `autonomous.auto_tags.*`.
- An Automation carries an optional `auto_tags` override (`enabled` plus the three templates; an empty template inherits the daemon's). Each Automation member carries an optional `stage` (at most 64 characters); `insert_member` takes `stage`.
- New `POST /api/automations/{id}/stages/rename` with `{expected_version, from, to, actor?, reason?}`; 400 for an empty or over-long name or a name another member uses, 404 when no member has the stage `from`, 409 for a stale version.
- Tags carry `system: true` when the daemon keeps them; the tag rename, move and delete calls refuse a system tag.
- `GET /api/autonomous/progress` and `/progress/trend` take repeatable `tag` plus `tag_match=any|all` (400 on another value) and return a `scope` string; `GET /api/sessions` takes the same `tag` and `tag_match` (a session matches on its own or inherited tags).
- MCP, CLI (`automation rename-stage`, `--tag` and `--tag-match` flags) and the comm channel (`automation rename-stage`, `tag=` and `tag_match=` tokens) carry the same. OpenAPI is updated. A draft handoff is in `docs/plans/parity-issues/3f6d0001.md`.

**New strings (EN values; DE, ES, FR and JA are in the parent release and need the same keys).**

- `settings_auto_tags_group`: Automatic tags
- `settings_auto_tags_group_help`: Tags datawatch gives each Automaton for its Automation, stage and kind. Templates may use {automation}, {stage} and {kind}.
- `settings_auto_tags_enabled`: Tag Automata automatically
- `settings_auto_tags_automation_template`: Automation tag template
- `settings_auto_tags_stage_template`: Stage tag template
- `settings_auto_tags_kind_template`: Kind tag template
- `settings_auto_tags_kind_labels`: Kind labels (kind:label, comma-separated)
- `tag_system_locked`: A system tag: datawatch keeps its name and parent, and it cannot be deleted
- `tag_system_badge`: system
- `tag_filter_group_automation`: Automation
- `tag_filter_group_stage`: Stage
- `tag_filter_group_kind`: Kind
- `tag_filter_group_other`: Other tags
- `automation_stage_label`: Stage
- `automation_stage_placeholder`: Optional stage, e.g. build
- `automation_rename_stage`: Rename stage
- `automation_rename_stage_to`: New stage name
- `automation_stage_too_long`: A stage name can have at most %1$d characters
- `automation_auto_tags_section`: Automatic tags
- `automation_auto_tags_hint`: Override the daemon's automatic tag settings for this Automation. An empty template uses the daemon's.
- `automation_auto_tags_mode`: Automatic tagging
- `automation_auto_tags_mode_inherit`: Use the daemon setting
- `automation_auto_tags_mode_on`: On
- `automation_auto_tags_mode_off`: Off
- `automation_auto_tags_automation_template`: Automation tag template
- `automation_auto_tags_stage_template`: Stage tag template
- `automation_auto_tags_kind_template`: Kind tag template
