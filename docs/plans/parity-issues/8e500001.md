Parent release: datawatch v9.100.0 (placement auto-tags on sessions and Automata).

**Screens.** (1) Session list: a "Group by placement" selector (no grouping, or one placement axis) with a "No <axis> tag" bucket and a per-group "Only this tag" filter. (2) Dashboard, tree and Gantt: a placement filter (one placement tag, or a whole axis such as `compute:*`). (3) The Tags menu: a "Placement tags (system)" section, read-only. (4) Automaton detail: an "Inherited from this Automaton's sessions (read-only)" tag set. (5) Settings, Automata: a "Placement tags" group (master switch, a switch and a template field for each of compute, peer, backend, lane, role and project).

**API contract.**
- Every session JSON carries `system_tags` (for example `["compute:node-a","backend:pi","lane:default","role:worker"]`), read-only; a retry on another node replaces the whole list. Local work carries no `peer:` tag.
- Every Automaton JSON carries `inherited_tags`, the read-only union of the system tags of its sessions (absent when none). Its own `tags` stay the operator's.
- `GET /api/autonomous/tags?system=true` lists the system tags; `&axis=lane` narrows to one axis. System tags cannot be renamed, moved or deleted (409).
- New config keys, all in `GET /api/config` and settable with `PUT /api/config`: `autonomous.tags.placement.enabled` (default true), and for each axis in compute, peer, backend, lane, role and project, `autonomous.tags.placement.<axis>.enabled` (default true; project false) and `autonomous.tags.placement.<axis>.template` (defaults `compute:{node}`, `peer:{peer}`, `backend:{backend}`, `lane:{lane}`, `role:{role}`, `project:{project}`). A template missing its placeholder is a 400. The list-valued `custom` axes are config-file only.
- MCP, CLI and the chat channel carry the same settings. OpenAPI is updated. A draft handoff is in `docs/plans/parity-issues/8e500001.md`.

**New strings (EN values; DE, ES, FR and JA are in the parent release and need the same keys).**

- `tag_inherited_title`: Inherited from this Automaton's sessions (read-only)
- `tag_inherited_mark`:  (inherited)
- `sessions_group_none`: No grouping
- `sessions_group_tip`: Group the session list by a placement (system) tag
- `sessions_group_by_label`: Group by placement
- `session_group_count_one`: 1 session
- `session_group_count_other`: sessions
- `session_group_filter_on`: Only this tag
- `session_group_filter_off`: Show all sessions
- `sessions_group_untagged`: No %1$s tag
- `tags_menu_placement`: Placement tags (system)
- `placement_tag_tip`: Placement tag — set by the machine
- `settings_placement_group`: Placement tags
- `settings_placement_group_help`: Placement (system) tags are derived by the machine for every session it creates — compute:<node>, peer:<name>, backend:<llm>, lane:<lane>, role:<role>, project:<name>. Enabling an axis adds its tag to sessions and lets the UI group and filter by tag or axis.
- `settings_placement_enabled`: Derive placement tags
- `settings_placement_compute`: compute axis
- `settings_placement_peer`: peer axis
- `settings_placement_backend`: backend axis
- `settings_placement_lane`: lane axis
- `settings_placement_role`: role axis
- `settings_placement_project`: project axis
- `settings_placement_compute_template`: compute tag template
- `settings_placement_peer_template`: peer tag template
- `settings_placement_backend_template`: backend tag template
- `settings_placement_lane_template`: lane tag template
- `settings_placement_role_template`: role tag template
- `settings_placement_project_template`: project tag template
- `dash_filter_placement_tip`: Filter the dashboard, tree and Gantt to one placement (system) tag, or to a whole axis (compute:*)
- `dash_filter_placement_all`: All placement tags
- `dash_filter_placement_axis`: %1$s (whole axis)
