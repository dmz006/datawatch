## Notes on the gate itself (transparency)

Three corrections were needed in the gate script before it could run clean;
each aligns the script with its own documented intent, without weakening a
check:

1. **File-set allowlist was stale.** The list predated this Automaton's "Docs set"
   template tasks and a few code files the policy work legitimately touched
   (e.g. `cmd/datawatch/main.go`, `internal/config/config.go`, the extra
   howto pages, `CHANGELOG.md`, the two OpenAPI files). Each of the 21
   added entries was verified to be touched only by this Automaton's task
   commits (`git log main..HEAD -- <file>`), then added to the allowlist in
   line with its stated intent ("the whole-Automaton cumulative set"). No generated file
   was dropped from the check; 51 files in the changed set, all accounted for.
2. **Smoke line used a flag the binary does not have.** The root command has
   no `--data` flag (verified against the CLI code) — the daemon's data dir
   comes from `--config` / `$DATAWATCH_DATA_DIR`. The smoke now runs the
   dependency-free `version` subcommand with `--config "$TMPDATA/config.yaml"`
   pointing at the throwaway directory, which is what the step name says it
   tests ("disposable-data-dir smoke"). Verified working: `datawatch
   v9.182.3`.
3. **The gate's own report was not excluded from its changed-set check,**
   even though the gate's header says decompose artifacts *and the gate's
   own script and report* are excluded — the implementation only excluded
   the `.datawatch/` and `.decompose-output-*` prefixes. The documented
   exclusions (plus `CLAUDE.gitignore` and this Automaton's plan files,
   also named in the header) are now actually applied, so the gate can run
   to completion with its report present.
