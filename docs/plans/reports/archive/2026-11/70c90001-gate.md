## Audit logging decision (item 5)

Audit logging (B16): N/A for the capability and permission events in the trace.

They are a read-only, redacted copy for the timeline. The federation capability denials and permission
decisions they mirror are already audited where they happen (the federation capability gate and config writes
keep their audit entries, JSON lines with the CEF mirror in `internal/audit`). The trace store is not a
security audit trail: it is pruned by `tracing.retention_days`, can be switched off and records at summary
level by default. A second CEF writer for a copy would duplicate the SIEM feed. Forwarding trace events to a
SIEM would be a separate item that adds `FormatCEFLine` and an escape test for the trace kinds. The reviewer
is asked to confirm this decision. The same decision is recorded in `docs/plans/2026-11-04-agent-tracing.md`.

- **TS-847** (`bash scripts/run-tests.sh --stories=TS-847`): 1 passed, 0 failed, 0 skipped.
  The first runs did not pass, and the run found a real defect: with "Errors only" on, the Trace card showed
  `0 of 3 events shown` for a failed tool result whose outcome was `error: no such file`. The card's
  `traceEventIsError` compared the outcome exactly (`error`, `failed`, `denied`, `timeout`) while the daemon's
  `trace.IsError` treats any outcome that starts with `error` or `fail` as a failure. Fixed in
  `internal/server/web/app.js` to mirror the daemon (prefix match on `error` and `fail`, exact `denied`; the
  `timeout` entry is dropped because the daemon does not count it) and covered by a new unit test in
  `app-trace-card.test.js`. The pass above is after that fix, on a binary rebuilt from this tree.
