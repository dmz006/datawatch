# TLS verification and JS sanitization alert decisions

Scope: open code-scanning alerts for disabled certificate validation (Go and JS) and the JS sanitization rules that fire in test files. Alert numbers and lines are as reported at triage time.

## Per-node TLS option

Nodes now carry an explicit `tls_insecure_skip_verify` field (`compute.Node`, mirrored in the config node struct, documented in `docs/implementation.md`). The zero value verifies certificates, so existing configs keep working for any node with a valid certificate; a node with a self-signed certificate needs the one-line opt-out. Tests: `internal/server/node_usage_tls_test.go` (httptest TLS server with a self-signed cert: the probe fails by default and succeeds with the opt-out).

Other node probes still skip verification and were left alone (outside this task): `internal/server/compute.go` (monitoring stub fetch, models list) and `internal/compute/probe.go` (`probeHTTP`). They can read the same field when the operator wants them tightened.
