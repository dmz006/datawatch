## Latent timing and port patterns in the dns package (not observed to fail)

### 1. `freeUDPPort` bind-close-rebind race — `internal/messaging/backends/dns/server_test.go:16-28`
- The helper binds a loopback UDP socket on an ephemeral port (port 0), reads the assigned port, and calls `conn.Close()` at line 28.
- The port is used later in `TestServerIntegration` (`server_test.go:33`, server created at 46) and `TestClientExecute` (`server_test.go:202`, server created at 215). Between close and the server's own bind, another process could take the port.
- Classification: **fixed-port / close-then-rebind race**. Kernel ephemeral-port reuse right after close is unlikely on Linux, which fits zero observed failures across 360 iterations.
- Suggested direction (not applied): have the server bind `:0` and report its real address, or pass in an already-open listener.
- Scope: this helper exists only in the dns package. A grep found no `freeUDPPort` definition or use anywhere else under `internal/` or `cmd/`.

### 2. Fixed startup sleeps — `server_test.go:61` and `server_test.go:222`
- `time.Sleep(500 * time.Millisecond)` stands in for "server is listening".
- At line 61 the `serverErr` check (lines 62–66) is non-blocking. A bind or subscribe failure that arrives after 500ms is missed, and the client query then fails with a timeout instead of a clear startup error.
- At line 222 there is no startup-error check at all. A slow start on a loaded machine would surface as a client `Execute` error.
- Classification: **wall-clock time.Sleep wait** (readiness is guessed, not observed).
- Suggested direction (not applied): poll the UDP port with a deadline, or wait on a ready channel.

### 3. Nonce TTL sleep — `internal/messaging/backends/dns/nonce_test.go:27-37`
- `NewNonceStore(100, 50*time.Millisecond)`, `Check("expired")`, then `time.Sleep(100 * time.Millisecond)`.
- Correction to the earlier report: this test **cannot fail from the sleep**. `time.Sleep` only waits at least the requested duration, so the second `Check` always sees `now.Sub(t) > 50ms`. It is deterministic. It uses a wall clock, but it is not a flake risk.
- Classification: **wall-clock sleep, but deterministic** (no action needed for flakiness).

### 4. Nonce LRU eviction tie-break — `internal/messaging/backends/dns/nonce.go:52-62`, test `nonce_test.go:39-56`
- Eviction picks the entry with the oldest stored `time.Now()` by iterating a map. If two timestamps are equal, the first one the map yields wins, and map order is randomized.
- The test then asserts that `a` is accepted again. That holds if `a` is evicted, but a tie could evict `b` or `c` instead. The test's comment (`nonce_test.go:54`) notes that "LRU with map is approximate", and it asserts nothing about `b`.
- On Linux the nanosecond clock makes ties very unlikely, which fits zero observed failures. On a platform with a coarse clock (Windows timer resolution is much coarser), ties are plausible. This is reasoning, not an observation.
- Classification: **map-iteration nondeterminism on timestamp ties** (latent, platform-dependent).
- Suggested direction (not applied): track insertion order explicitly (e.g. a slice or `container/list`) so eviction is deterministic.

### 5. Broader sleep usage (not classified)
- There are 120 `time.Sleep` calls across `_test.go` files under `internal/` and `cmd/` (counted with `grep`). Only the dns package patterns above were inspected. A full classification is a follow-up if flakes are reported elsewhere.
