## Why this is a major version, not a feature release

`docs/plans/README.md` has carried a "v9.0.0 — Memory Lifecycle Complete"
milestone entry since 2026-09-15, gated on BL385+386+387 (the three-part
memory lifecycle trilogy: subprocess scope isolation, lifecycle management,
PRD integration). All three shipped months ago (BL385 v8.29.0, BL386
v8.30.0, BL387 v8.31.0–v8.33.0) but the milestone itself was never formally
cut — the backlog entry's status text (`in-progress`/`planned`) went stale
and was never updated, and its referenced plan doc
(`docs/plans/2026-09-15-v9-memory-lifecycle-major.md`) was never written.

v9.0.0 ships no major new feature beyond what's already in 8.73.1 — it is
the formal milestone cut for memory-lifecycle completeness, bundled with the
routine major-release housekeeping `docs/release-checklist.md` and
`AGENT.md`'s major-release-specific rules require: a full E2E pass, a
backlog-status correction sweep, the Claude model-alias refresh, a
container/Helm-chart maintenance audit, and a README restructure (adding
the `## Current release` marquee the checklist calls for, which never
existed).

  `dwbuilder` stage: `COPY . .` → build → `COPY --from=dwbuilder /out/datawatch

  every `agent-*`/`parent-full` image from current source on **every**
  release tag push, unconditionally — this release's tag triggers that
  automatically, closing the gap without any extra local step. Confirmed
  the build args (`GO_VERSION=1.26.6`/`MINIDEB_TAG=bookworm`) are current,
  not stale pins. `charts/datawatch/Chart.yaml`'s `appVersion` (stale at
  `5.26.22`, ~80 releases behind) bumped to `9.0.0` to track this release;
  chart `version` (0.23.0) left unchanged — no template/values changes.

## E2E results

Full `scripts/run-tests.sh` run, isolated sandbox daemon
(`/home/dmz/workspace/datawatch-88cd0c/`, outside the repo tree, never
production) — **672 passed, 1 failed, 15 skipped, 2819s (~47 min) total.**

**The 1 failure**, TS-557 (`release-smoke.sh exited with code 1`): root
cause was 9 plan docs older than the 7-day cutoff still sitting directly in
`docs/plans/` instead of `docs/plans/historical-plans/` — `release-smoke.sh`
runs `tidy-plans.sh --dry-run` as a release gate and fails when it finds any.
8 of the 9 were already-committed, clean files (6 identity-scaffold docs
from 2026-09-21, 2 from 2026-09-30); one
(`2026-09-29-harness-research-candidates-enrichment.md`) was untracked,
belonging to a different, still-in-progress piece of work elsewhere in this
shared working tree — `git mv` can't move an untracked file, so
`tidy-plans.sh` aborted partway through (`set -euo pipefail`) after moving
6 of the 8 tracked files. Fixed by relocating the untracked file with a
plain `mv` (preserves its untracked status at the new path, doesn't
commandeer it) and re-running `tidy-plans.sh` for the remaining 2 tracked
files. Re-ran `release-smoke.sh` standalone afterward to confirm: **185
passed, 0 failed, 33 skipped (gated on unconfigured subsystems), exit 0.**

**The 15 skips** are all legitimate infrastructure-floor gaps in this
sandbox, none a code bug: 1Password CLI not installed (1), Signal not
configured (1), Tailscale not configured (3), an Ollama vision model that
crashed mid-run cascading into 3 related vision/council/compute-node skips,
a compute-node unreachable (503) from that same crash (1), and TS-695 (the
two-real-Ollama-node parallel-LLM Automata test) hitting its own documented
30-minute soft-skip branch — both compute nodes were confirmed live
simultaneously (its primary assertion), the PRD just hadn't reached a
terminal state within the budget, which the story's own code treats as an
expected skip, not a failure.

No other real failures found. No code regression required a fix — the one
real gap was pre-release housekeeping, not a bug in any of this release's
actual changes.
