## Judgment calls

1. Triage card placement: the Needs-attention/triage card
   (`#automationTriageCard`) stays on the Chains sub-tab, rendered above the
   list (app.js, `_AUTOMATION_SUBTABS` entry for `chains`). Rationale: it
   enumerates the failed/blocked Automata that need an operator; burying it on
   the non-default Overview sub-tab would hide operator-waiting items and
   regress the pre-split behavior. The capacity/usage/progress cards went to
   Overview.
2. English placeholders in the non-English locale bundles:
   `automation_subtab_overview` and `automation_subtab_chains` ship as
   English strings in de.json, es.json, fr.json and ja.json for now. They are
   covered by the explicit PENDING_TRANSLATION allow-list in
   internal/server/web/app-automation-locales.test.js, which still requires
   the same key set, placeholder parity, ≥80% translation of the other
   Automation values, and absence of internal references in every bundle.
3. node --test invocation (step 2): the directory-argument form specified by
   the gate fails with MODULE_NOT_FOUND on node v24.15.0 in this environment
   even for a scratch directory holding one passing test, i.e. the failure is
   the invocation form on this build, not the suite; the glob
   `internal/server/web/*.test.js` spans the same 123 test files and was used
   for the pass/fail counts. The literal command's exit code is reported as
   FAIL here rather than smoothed over.
4. Guard stories (step 7): cited, not re-run, because app.js and style.css
   predate the 08:38 record; the cited FAIL is reported as FAIL (attempt 1
   relabeled it PASS, which was the defect being corrected). The record's own
   triage (all 35 findings pre-existing Observer drift, 0 attributable to this
   change) is quoted as-is, not re-decided.
5. Tree-state side effect of the step-6 command: scripts/e2e-pwa.sh runs
   `npm ci`/`npm install` in scripts/test-stories/pwa, and npm replaces the
   tracked `node_modules` symlink (git mode 120000, present in HEAD) with a
   real directory — the uncommitted deletion seen after attempt 1. It is a
   side effect of the spec-mandated command, not of this change's code; the
   symlink was restored (git restore) after the run and the working tree is
   left with no diff outside this report.
